# Реестр моделей `sllm-model`

Дата: 2026-11-10. Крейт: `crates/sllm-model`.

## Что делает

`ModelRegistry` рекурсивно сканирует каталог, читает только заголовки GGUF (без
весов), группирует файлы в один пакет на модель и оценивает, влезает ли модель
в доступную память.

Публичный API:

```rust
ModelRegistry::discover(root) -> Result<ModelRegistry, ModelError>
ModelRegistry::discover_with(root, probe: &dyn GgufProbe, config: &EngineConfig)
    -> Result<ModelRegistry, ModelError>

registry.packs() -> &[Pack]
registry.get(id) -> Option<&Pack>
registry.view(avail_mb) -> RegistryView
registry.to_json(avail_mb) -> Result<String, ModelError>
registry.to_json_pretty(avail_mb) -> Result<String, ModelError>

pack.status(avail_mb) -> Status   // ready | storage-bound | unsupported
pack.fit(avail_mb) -> Fit         // fits | tight | no | unknown
pack.reason(avail_mb) -> String   // короткая причина на английском
pack.view(avail_mb) -> ModelView
```

`GgufProbe` — точка инъекции для тестов. Продакшн-реализация `FsProbe` читает
`gguf::read_meta` + `gguf::preflight` и кэширует результат по
`(path, size, mtime, ctx, kv)`. `ModelRegistry::discover` использует общий
`FsProbe::shared()`, поэтому повторное открытие экрана моделей не перечитывает
те же заголовки. Кэш живёт до конца процесса; веса не читаются никогда.

## Группировка

| Что | Правило |
| --- | --- |
| Base | обычный `.gguf`, не adapter/mmproj/шард |
| Split | имя `*-00001-of-000NN.gguf`; fallback — `split.count`/`split.no` + `general.name`. Все шары → один пакет |
| LoRA | `general.type=adapter` или `lora` в имени |
| mmproj | `clip.*`/`arch=clip` в заголовке или `mmproj`/`clip` в имени |
| Companion | LoRA/mmproj ищется в той же папке по самому длинному общему префиксу токенов имени; если база в папке одна — привязывается к ней. При равенстве приоритет у supported-кванта, затем у файла большего размера |
| Dedupe | одинаковые `(имя файла в нижнем регистре, точный размер)` в разных папках считаются копией. Разные кванты имеют разные имена или размеры и не скрываются |
| ID | slug имени base-файла без суффикса шардов. При коллизии — суффикс из FNV-1a хэша `(base path, size, quant)` |
| Сортировка | `sizeBytes` по убыванию, затем `id` |

Шары, LoRA и mmproj никогда не попадают в список как отдельные модели.
Companion без найденной базы в реестр не выводится.

`estimate_mb` для split-модели считается по суммарному размеру всех шаров плюс
KV-кэш из `EngineConfig` (`ctx`, `kv`).

## JSON для JNI

Поля стабильные, camelCase:

```json
{
  "root": "models",
  "availMb": 8192,
  "models": [
    {
      "id": "ternary-bonsai-2-4b-q2-0",
      "name": "Ternary-Bonsai-2-4B",
      "arch": "qwen35",
      "quant": "Q2_0",
      "sizeBytes": 1212103520,
      "sizeGb": 1.13,
      "estimateMb": 1955,
      "basePath": "ternary/Ternary-Bonsai-2-4B-Q2_0.gguf",
      "files": [
        { "role": "base", "name": "Ternary-Bonsai-2-4B-Q2_0.gguf",
          "path": "ternary/Ternary-Bonsai-2-4B-Q2_0.gguf", "bytes": 1212103520 },
        { "role": "lora", "name": "Ternary-Bonsai-2-4B-Uncensored-LoRA.gguf",
          "path": "ternary/Ternary-Bonsai-2-4B-Uncensored-LoRA.gguf", "bytes": 2368992 }
      ],
      "capabilities": ["Text"],
      "chatTemplate": true,
      "layers": 32,
      "context": 262144,
      "moe": false,
      "expertCount": 0,
      "expertsActive": 0,
      "ternary": true,
      "hasLora": true,
      "loraCount": 1,
      "hasMmproj": false,
      "shardsTotal": 1,
      "shardsPresent": 1,
      "status": "ready",
      "fit": "fits",
      "reason": "Preflight passed; needs about 1.9 GB, 8.0 GB available."
    }
  ]
}
```

`license` и `shard` опускаются, если их нет. `capabilities` — человекочитаемые
метки: `Text`, `Vision`, `Audio`, `Video`, `Embedding`, `Rerank`, `Diffusion`,
`TTS`.

### Статусы

- `unsupported` — preflight не прошёл (квант/архитектура/битый файл) или не
  хватает шардов split-модели;
- `storage-bound` — `estimateMb > availMb`;
- `ready` — preflight прошёл и оценка влезает.

### Fit

- `fits` — `estimateMb <= availMb`;
- `tight` — влезает только с запасом 1 GB (`estimateMb <= availMb + 1024`);
- `no` — не влезает даже с запасом;
- `unknown` — preflight не прошёл.

## Реальные модели в `models/`

`cargo run -p sllm-model --example registry -- models 8192` сгруппировал:

| `ternary-bonsai-2-4b-q2-0` | Ternary-Bonsai-2-4B | `qwen35` | Q2_0 | 1 212 103 520 B (1.13 GiB) | 1 955 MB | `ready`, LoRA companion |
| `ternary-bonsai-2-4b-ptq1-0` | Ternary-Bonsai-2-4B | `qwen35` | PTQ1_0 | 949 549 920 B (0.88 GiB) | 1 705 MB | `unsupported` (`E_QUANT_UNSUPPORTED`) |
| `qwen2-5-0-5b-instruct-q4-k-m` | Qwen2.5 0.5B Instruct | `qwen2` | Q4_K_M | 397 808 192 B (0.37 GiB) | 932 MB | `ready` |

LoRA `Ternary-Bonsai-2-4B-Uncensored-LoRA.gguf` (2 368 992 B) привязан к
Q2_0-паку, а не показан отдельной моделью. Clover — MoE 256 экспертов / 8
активных, 40 слоёв. Значения `estimateMb` — из `sllm-core::gguf::estimate_mb`
для `ctx=4096`, `kv=q8_0`; они не выдуманы в этом крейте.

В реальном каталоге нет split- и mmproj-файлов, поэтому эти сценарии покрыты
синтетическими тестами на временных каталогах.

## Тесты

```powershell
$env:CARGO_TARGET_DIR='target/agent-registry'
cargo test -p sllm-model
```

11 тестов: split (полный и неполный), LoRA, приоритет supported-кванта, mmproj
+ Vision, dedupe копий, разные кванты, коллизия имён, unsupported quant, fit,
camelCase JSON и обнаружение реальных `models/`. Preflight 12 GB Clover читает
только заголовок; файлы не копируются.

## Подключение к `crates/sllm-webapp`

Сейчас `nativeModels` сам вызывает `sllm_core::model::scan_dir` и собирает JSON
вручную. Замена:

1. Добавить зависимость:

   ```toml
   sllm-model = { path = "../sllm-model" }
   ```

2. В `crates/sllm-webapp/src/lib.rs` заменить тело `scan`:

   ```rust
   fn scan(dir: &str, avail_mb: u64) -> String {
       match sllm_model::ModelRegistry::discover(dir) {
           Ok(registry) => match registry.to_json(avail_mb) {
               Ok(json) => json,
               Err(error) => serde_json::json!({
                   "availMb": avail_mb,
                   "models": [],
                   "error": error.to_string(),
               })
               .to_string(),
           },
           Err(error) => serde_json::json!({
               "availMb": avail_mb,
               "models": [],
               "error": error.to_string(),
           })
           .to_string(),
       }
   }
   ```

   Сигнатура JNI-метода `nativeModels(String dir, int availMb)` не меняется.

3. UI сейчас читает `caps`, `note`, `estimateGb`. Новый контракт:
   `capabilities`, `reason`, `estimateMb`. Либо обновить поля в Preact, либо
   добавить в JS-адаптер:

   ```js
   const view = {
     ...model,
     caps: model.capabilities,
     note: model.reason,
     estimateGb: Math.round((model.estimateMb / 1024) * 100) / 100,
   };
   ```

   Поля `id`, `name`, `arch`, `quant`, `sizeGb`, `layers`, `context`, `status`
   совпадают по смыслу; `status` использует те же значения
   `ready|storage-bound|unsupported`.

После переключения `scan_dir`, ручной `HashSet` для dedupe и эвристики
`has_companion` в webapp больше не нужны: всё делает реестр.
