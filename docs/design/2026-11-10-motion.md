# Motion & UX — Paper & Ink (2026-11-10)

> Внедрено 2026-11-10: motion-токены, reduced motion (`data-motion`),
> списки без повторного stagger, убраны blur у nav/шапки, убраны анимации
> истории сообщений. Стриминг/Stop и «New text below» — в работе (JNI).

Дизайн-спека движения для `web/` (Preact + CSS в системном WebView). Только проектирование: код UI не менялся. Опорные документы: `docs/design/2026-11-09-editorial-ui.md`, `web/src/styles.css`, `web/src/app.tsx`, `docs/design/screens/device-*.png`.

## 1. Принципы

Движение здесь — не украшение, а «работа с бумагой»: лист кладут, строку подчёркивают, карточку сдвигают. Поэтому коротко, с мягкой посадкой, без пружинного отскока и без движения ради движения. Одна анимация объясняет одно изменение; одновременно двигается максимум одна крупная поверхность. Всё, что можно показать мгновенно, показывается мгновенно.

Второй принцип — движение не должно мешать чтению. Текст не «влетает» по буквам, список не переигрывается при каждом фильтре, а стриминг не дёргает viewport. Третий — reduced motion является полноценным режимом, а не отключением CSS «через костыль».

Ориентиры 2025–2026: M3 Expressive ввёл пружинную физику движения (май 2025) [1]; WCAG 2.3.3 (AAA) требует возможности отключить необязательное движение (обновлено 16.09.2025) [4]; NN/g отдельно предупреждает об автопрокрутке стримящегося ответа (24.04.2026) [9]. Мы берём из M3 «standard»-профиль без заметного overshoot: он дисциплинированнее expressive и не размывает serif-текст.

## 2. Motion-токены

### Длительности

| Токен | Значение | Кривая | Где |
|---|---:|---|---|
| `--motion-instant` | `0ms` | — | reduced motion, смена цвета текста |
| `--motion-fast` | `120ms` | `--ease-out` | press release, hover, chip, caret fade |
| `--motion-base` | `200ms` | `--ease-out` | строки, сообщения, toggle, nav |
| `--motion-slow` | `320ms` | `--ease-out` | первый показ экрана, карточки |
| `--motion-exit` | `140ms` | `--ease-in` | закрытие, удаление из фильтра |
| `--motion-screen` | `280ms` | `--ease-out` | открытие чата на телефоне |
| `--stagger-row` | `18ms` | — | строки списка, максимум 6 |
| `--stagger-card` | `20ms` | — | карточки моделей, максимум 5 |
| `--delay-head` | `40ms` | — | поиск после заголовка |

Обоснование: 120 мс — примерно 7 кадров при 60 Гц, движение считывается, но не тормозит; 200 мс — 12 кадров, база для небольших поверхностей; 320 мс — 19 кадров, предел для повторяемого UI-перехода. Всё, что длиннее 400 мс, в чате воспринимается как задержка. На 120 Гц те же значения дают 14, 24 и 38 кадров: время не зависит от частоты, поэтому анимации задаются в миллисекундах, а не в кадрах.

`18ms` — это примерно один кадр при 60 Гц: строки появляются волной, а не «очередью». Шесть строк дают 90 мс общей задержки; сам список входит за 290 мс, а с задержкой старта на экране — ≤400 мс. Задержка 40 мс есть только у поиска на первом показе; интерактивные элементы никогда не ждут анимацию.

Сверка с M3 по реализации [2]: standard spatial springs дают settle 229/324/496 мс, effects — 149/230/326 мс. Наши 120/200/320 — сжатые effects-значения (149/230/326) под более плотный редакционный ритм; 280–320 мс — для экранов. Expressive fast-spatial с ζ=0,6 сознательно не используем: отскок противоречит Paper & Ink и ухудшает читаемость текста.

### Кривые

| Токен | Значение | Смысл |
|---|---|---|
| `--ease-out` | `cubic-bezier(.16, 1, .3, 1)` | вход: быстрый старт, мягкая посадка |
| `--ease-in` | `cubic-bezier(.3, 0, .8, .15)` | выход: сразу уходит, затем ускоряется |
| `--ease-move` | `cubic-bezier(.65, 0, .35, 1)` | перемещение индикатора между равными позициями |
| `--ease-standard` | `cubic-bezier(.2, 0, 0, 1)` | нейтральные изменения состояния |

Четырёх кривых достаточно. Мы не вводим `linear()`-пружины в v1: CSS-кривая не переносит скорость при прерывании, а на прерываниях (быстрый back, повторный tap) пружина «перезапускается» и выглядит хуже. Пружины понадобятся только для drag-жеста back, когда появится predictive back (фаза 2).

## 3. Производительность

Бюджет: 16,7 мс на кадр при 60 Гц и 8,3 мс при 120 Гц. На MI 8 (SD845) main-thread бюджет для JS — не более 8 мс на кадр, иначе compositor не успевает. Любая задача >50 мс считается long task и фиксируется в Performance.

Правила:

- Анимируем только `transform` и `opacity`. `width`, `height`, `top`, `left`, `margin`, `padding`, `box-shadow`, `filter`, `backdrop-filter` — запрещены: они вызывают layout/paint.
- `will-change: transform, opacity` ставим только на элемент, который начнёт двигаться в ближайшие 200 мс, и снимаем на `animationend`/`transitionend`. Максимум 3 promoted-слоя. На `.chat-row`, `.msg`, `.model-card` — никогда: это десятки слоёв и лишняя память.
- `contain: layout paint style` на строках и карточках; `content-visibility: auto` с `contain-intrinsic-size` — только для длинного списка чатов, не для стримящегося сообщения.
- Не читаем `scrollHeight`/`getBoundingClientRect` в цикле перед записью. Сначала все чтения, потом все записи, один `requestAnimationFrame`.
- Списки не анимируем целиком. CSS-анимация на `.chat-row` сейчас перезапускается при каждом фильтре, потому что элементы пересоздаются. Нужен класс `is-entering` только для реально новых строк; остальные не двигаются. При поиске остающиеся строки стоят на месте.
- Текст не анимируем: ни по буквам, ни по словам, ни `letter-spacing`, ни `font-size`. Стриминг обновляет только последний текстовый блок, батчами по 32 мс, без Preact-перерендера всего списка. Метаданные и бейдж обновляются раз в 100 мс.
- `scroll-behavior: smooth` на `.messages` отключаем на время стриминга: он конфликтует с автоскроллом и с reduced motion. Плавный скролл — только для кнопки «вниз», 220–300 мс.
- `backdrop-filter` на нижней навигации и шапке чата убираем: на SD845 размытие поверх скролла — прямой путь к jank. Заменяем на непрозрачный `rgba(255,252,247,.98)`; на Pad 2 можно вернуть blur только по флагу устройства (или если WebView поддерживает `prefers-reduced-transparency`).
- Текущий демо-стриминг делает `setMessages(prev => prev.map(...))` каждые 52 мс — это реконсиляция всего списка. В продакшене: буфер токенов + запись в DOM последнего блока, состояние — раз в 100 мс.

## 4. Chats

**Первый показ.** Заголовок — 240 мс, `translateY(6px)` + opacity; поиск — 200 мс с задержкой 40 мс; строки стартуют на 100 мс, идут 200 мс, stagger 18 мс, максимум 6. Всё вместе ≤400 мс. Только при входе в раздел, не при каждом рендере.

**Pinned / Recent.** Переключение — не FLIP через границу секций: строка гаснет 120 мс, список мгновенно перестраивается, строка появляется на новом месте 180 мс + 4px. Это честнее, чем анимировать высоту и заголовки. Если позже понадобится FLIP — только для ≤8 строк и только `transform`.

**Открытие чата, телефон.** Не полноэкранный push, а «наложение листа»: панель чата `translateX(28px) → 0` + opacity, 280 мс; список уходит на `-12px` и до opacity .72; скрим 0 → .16 за 220 мс. Назад — 220 мс, фокус возвращается на выбранную строку. Это меньше вестибулярной нагрузки, чем слайд на всю ширину.

**Планшет.** Выбор чата — crossfade 160 мс + 4px; активная строка получает 3px accent-полосу через `scaleY(0→1)` за 160 мс. Панели не сдвигаются: контекст остаётся на месте.

**Поиск.** Debounce 80 мс. Оставшиеся строки не двигаются; удалённые гаснут 100 мс; новые появляются 120 мс + 3px; stagger нет. Пустой результат — 160 мс opacity + 4px, иконка статична, без bounce. Кнопка очистки появляется 120 мс.

**Новый чат.** Нажатие «+» — scale .94 за 90 мс; список приглушается 120 мс; чат входит 280 мс. Фокус в композер — через 240 мс, когда основная часть перехода позади, чтобы клавиатура не спорила с анимацией.

## 5. Chat

**Появление сообщений.** История при открытии — мгновенно, без stagger: это контекст, а не новость. Новое сообщение пользователя — 160 мс, `translateY(6px)` + opacity; bubble не масштабируется, чтобы не мылить текст.

**Ожидание и стриминг.** Каретка появляется с первым токеном. Если TTFT >600 мс, показываем тихую строку «preparing…» с пульсацией opacity 1,1 с у точки 6px; при reduced motion — статичная точка. Токены не анимируются: текст просто дописывается. Каретка 2px, `steps(2, jump-none)`, 1 с; при завершении гаснет 120 мс, бейдж `streaming` сменяется метаданными за 160 мс. Обновление DOM — батчами 32 мс, только последний блок.

**Автоскролл.** Порог «прилипания» — 64px от низа. Следуем за низом, только пока блок ассистента меньше 60% высоты viewport. Как только ответ длиннее — фиксируем позицию и показываем «New text below ↓» (это тот же ответ). Если пользователь отлистал вверх более чем на 24px, автоскролл выключается сразу; при новом сообщении снизу появляется «1 new message ↓». Это соответствует рекомендации NN/g не тащить пользователя в конец длинного стрима [9]. Кнопка «вниз» — 160 мс вход, 120 мс выход; скролл 220–300 мс (нативный smooth), в reduced motion — instant; haptic `VIRTUAL_KEY`.

**Отправка / отмена.** Send → Stop: crossfade иконки 120 мс, ширина кнопки остаётся 40px. Отмена останавливает поток за 100 мс, каретка гаснет 120 мс, бейдж «stopped» появляется 140 мс, частичный текст сохраняется. Никакого collapse и «вздоха» интерфейса.

**IME.** `interactive-widget=resizes-content` (где WebView поддерживает; иначе — `visualViewport`); композер остаётся над клавиатурой. Нижняя навигация не `display:none`, а `translateY(100%)` + opacity за 160 мс — иначе контент прыгает. Подсказка гаснет 100 мс. Собственную анимацию клавиатуры не рисуем: системная уже есть. Back при открытой клавиатуре сначала закрывает её.

**Долгое нажатие / копирование.** Нативное выделение, без scale на сообщении. Один haptic `LONG_PRESS` при открытии контекстного меню. Toast «Copied» — 1,6 с, вход 160 мс, выход 120 мс, `role="status"`. Ошибка — без shake: 2px danger-полоса, 160 мс, haptic `REJECT`.

## 6. Models

**Первый показ.** Storage-карточка 240 мс; фильтры 200 мс с задержкой 40 мс; карточки стартуют на 80 мс, идут 220 мс, stagger 20 мс, максимум 5. На планшете две колонки: stagger по рядам 12 мс. Весь экран ≤400 мс.

**Активная модель.** Кольцо — псевдоэлемент с opacity 0→1 за 160 мс (не `box-shadow`: он paint). Кнопка меняет фон 140 мс, галочка scale .85→1 за 160 мс. Карточка не приподнимается: крупный scale размывает serif. Haptic `CONFIRM`.

**Fit-meter.** Только `transform: scaleX()` от левого края: 420 мс при первом показе, 240 мс при обновлении. `width` не анимируем. Числа статичны, без count-up: он раздражает и плохо читается screen reader.

**Фильтры.** Crossfade чипа 140 мс; «скользящая pill» не делаем — у чипов разная ширина, а анимация width = layout. Результаты — 140 мс crossfade, без повторного stagger. Пустой фильтр — 160 мс.

**Импорт.** Детерминированный прогресс: `scaleX` 120 мс linear, процент обновляется текстом. Если процент неизвестен — один сегмент 30% едет `translateX` 1,2 с linear, не бесконечный shimmer; при reduced motion — статичные 30%. Завершение: галочка .8→1 за 180 мс + `CONFIRM`, без конфетти. Ошибка — 2px danger-полоса, сдвиг 6px + opacity 160 мс, `role="alert"`, `REJECT`.

## 7. Settings

**Toggle.** 180 мс, кнопка 18px, трек меняет цвет 160 мс, нажатие scale .96 за 90 мс, haptic `VIRTUAL_KEY`. Без overshoot: переключатель — инструмент, не игрушка. Состояние дублируется `aria-checked`.

**Раскрытие групп.** Контент появляется opacity 0→1 + 4px за 120 мс, chevron поворачивается 180 мс, высота меняется мгновенно. Анимация `height` — это layout на каждом кадре; на MI 8 с пятью группами она даёт заметный jank. Мгновенная высота + fade читается как «лист развернули», и это честнее.

**Смена темы.** 180 мс crossfade только поверхностей (paper, card, line, accent-soft); цвет текста переключается на 80 мс, чтобы не проходить через серую середину. Никакого full-screen snapshot и View Transitions в v1: same-document transitions стали Baseline 14.10.2025 [8], но снимок всего экрана на SD845 может стоить 1–2 кадра и мылит текст. При reduced motion — мгновенно.

**Reduce motion.** Тумблер в Appearance; по умолчанию наследует систему, но может принудительно включить/выключить. Применяется сразу, сохраняется в настройках, не требует перезапуска.

## 8. Навигация

**Phone bottom nav.** Активная pill — один абсолютный элемент, который едет `translateX` между тремя позициями за 220 мс `--ease-move`; иконка и подпись меняют цвет 140 мс; нажатие scale .96 за 90 мс. При IME панель уезжает вниз 160 мс и гаснет, но занимает место — нет layout jump. Возврат 180 мс.

**Tablet rail.** Фон активного пункта 140 мс, 3px индикатор `scaleY(0→1)` 180 мс, без bounce иконок. Rail не двигается при смене раздела.

**Two-pane.** Список 356px фиксирован; выбор чата — crossfade 160 мс, панели не едут. На брейкпоинте 980px раскладка меняется мгновенно, без анимации: анимировать перестройку сетки бессмысленно и дорого.

**Переходы разделов.** Phone: crossfade + 6px за 200 мс, исходящий экран 120 мс; горизонтального слайда между вкладками нет — они равноправны. Back из чата — 220 мс. Predictive back (Android 13+) — фаза 2: прогресс жеста 1:1, порог 40%, settle 220 мс; системная анимация Android 15+ включается через `OnBackInvokedCallback` [6].

## 9. Доступность

`prefers-reduced-motion: reduce` отключает все пространственные переходы: остаются opacity 120 мс или мгновенная смена; stagger 0; каретка не мигает; прогресс статичен; автоскролл мгновенный; `scroll-behavior: auto`. Это соответствует MDN [5] и WCAG 2.3.3 [4]. Внутренний переключатель Reduce motion перекрывает системный и выставляется атрибутом `data-motion="off"` на `<html>`.

Вестибулярные триггеры: никакого parallax, zoom, spin, bounce и больших слайдов. Максимальный `translateY` контента — 8px, максимум `translateX` — 28px (только «лист» чата). Крупные поверхности меняются через opacity, а не через движение.

Фокус: кольцо 2px accent появляется мгновенно, без fade и задержки. После смены раздела фокус уходит на `h1` с `tabindex="-1"`; после открытия чата — на композер через 240 мс (или на заголовок для screen reader); после back — на выбранную строку.

Screen reader: `aria-live` не на всём списке сообщений. Отдельный визуально скрытый live-region сообщает только статусы: «Assistant is responding», «Response complete», «Generation stopped», «3 new messages below». Стримящееся сообщение имеет `aria-busy="true"`; токены не объявляются. Это предотвращает шторм announcements.

Haptics: `VIRTUAL_KEY` — nav, toggle, send/stop; `CONFIRM` — активная модель, завершение импорта; `REJECT` — ошибка; `LONG_PRESS` — контекстное меню. Уважаем системный `HAPTIC_FEEDBACK_ENABLED` [7]. Никаких вибраций на скролл, токены и декоративные события. Fallback `navigator.vibrate(10)` — только если JNI-моста нет и есть user gesture.

## 10. Анти-паттерны

| Анти-паттерн | Почему | Замена |
|---|---|---|
| bounce / elastic | вестибулярный триггер, мылит текст | `ease-out` без overshoot |
| parallax | прямо назван WCAG-триггером [4] | статичный фон |
| blur / glass | дорого на SD845, jank при скролле | непрозрачная бумага |
| бесконечный shimmer | шум, батарея, нет информации | determinate progress или тихий placeholder |
| анимация каждого токена | layout thrash + screen reader spam | батчи 32 мс, каретка |
| width/height/top/left | layout каждый кадр | transform/opacity |
| `transition: all` | случайно анимирует layout/paint | явные свойства |
| повторный stagger при фильтре | список «прыгает» | `is-entering` только для новых |
| smooth scroll при стриме | борьба с пользователем | instant + кнопка «вниз» |
| hover на touch | залипает после tap | `@media (hover: hover) and (pointer: fine)` |
| shake при ошибке | вестибулярный триггер и насмешка | цвет + текст + `REJECT` |
| confetti / celebration | не в характере Paper & Ink | галочка 180 мс |
| `will-change` на всём | слои и память | точечно, снимать после |

## 11. Сниппеты

Импорты опущены; классы совместимы с текущей разметкой, кроме новых `.nav-pill` и `.is-entering`.

**Токены и reduced motion.**

```css
:root {
  --motion-instant: 0ms;
  --motion-fast: 120ms; --motion-base: 200ms; --motion-slow: 320ms;
  --motion-exit: 140ms; --motion-screen: 280ms;
  --ease-out: cubic-bezier(.16, 1, .3, 1);
  --ease-in: cubic-bezier(.3, 0, .8, .15);
  --ease-move: cubic-bezier(.65, 0, .35, 1);
  --ease-standard: cubic-bezier(.2, 0, 0, 1);
  --stagger-row: 18ms; --stagger-card: 20ms;
}
:root[data-motion="off"] {
  --motion-fast: 1ms; --motion-base: 1ms; --motion-slow: 1ms;
  --motion-exit: 1ms; --motion-screen: 1ms;
  --stagger-row: 0ms; --stagger-card: 0ms;
}
@media (prefers-reduced-motion: reduce) {
  :root {
    --motion-fast: 1ms; --motion-base: 1ms; --motion-slow: 1ms;
    --motion-exit: 1ms; --motion-screen: 1ms;
    --stagger-row: 0ms; --stagger-card: 0ms;
  }
  .caret { animation: none !important; opacity: 1; }
  * { scroll-behavior: auto !important; }
}
:root[data-motion="off"] .caret { animation: none !important; opacity: 1; }
:root[data-motion="off"] * { scroll-behavior: auto !important; }
:root[data-motion="off"] .msg,
:root[data-motion="off"] .chat-row,
:root[data-motion="off"] .model-card { animation: none !important; }
```

**Вход строк списка (только для новых).**

```css
.chat-row.is-entering {
  animation: row-in var(--motion-base) var(--ease-out) both;
  animation-delay: min(calc(var(--i, 0) * var(--stagger-row)), 90ms);
}
@keyframes row-in {
  from { opacity: 0; transform: translateY(6px); }
  to   { opacity: 1; transform: translateY(0); }
}
.chat-row { contain: layout paint style; }
@media (prefers-reduced-motion: reduce) {
  .chat-row.is-entering { animation: none; opacity: 1; transform: none; }
```

**Preact: батчи токенов + «прилипание» к низу.** На `stream end` буфер нужно сбросить немедленно, не дожидаясь 32 мс.

```tsx
function useTokenBuffer(flush: (s: string) => void) {
  const buf = useRef(""); const raf = useRef(0); const last = useRef(0);
  return (chunk: string) => {
    buf.current += chunk;
    if (raf.current) return;
    const tick = (t: number) => {
      raf.current = 0;
      if (t - last.current < 32) { raf.current = requestAnimationFrame(tick); return; }
      last.current = t; flush(buf.current); buf.current = "";
    };
    raf.current = requestAnimationFrame(tick);
  };
}

function useChatScroll(ref: RefObject<HTMLDivElement>, dep: unknown) {
  const pinned = useRef(true); const [away, setAway] = useState(0);
  useEffect(() => {
    const el = ref.current!;
    const onScroll = () => {
      const near = el.scrollHeight - el.scrollTop - el.clientHeight < 64;
      pinned.current = near; if (near) setAway(0);
    };
    el.addEventListener("scroll", onScroll, { passive: true });
    return () => el.removeEventListener("scroll", onScroll);
  }, []);
  useLayoutEffect(() => {
    const el = ref.current!; if (!pinned.current) return;
    const last = el.lastElementChild as HTMLElement | null;
    if (!last || last.offsetHeight < el.clientHeight * .6) el.scrollTop = el.scrollHeight;
    else if (el.scrollTop + el.clientHeight < el.scrollHeight - 4) setAway(1);
  }, [dep]);
  return { away, jump() {
    const el = ref.current!; const reduce = matchMedia("(prefers-reduced-motion: reduce)").matches;
    el.scrollTo({ top: el.scrollHeight, behavior: reduce ? "auto" : "smooth" });
    pinned.current = true; setAway(0);
  }};
}
```
