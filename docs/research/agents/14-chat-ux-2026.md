## TL;DR

1. **Наш главный разрыв — не в чате, а в списке чатов.** Сейчас есть поиск, Pinned и «Recent», но нет действий над чатом, групп по времени, архива, проектов, черновиков и bulk-операций. Чат, который не помечен pinned, быстро теряется.
2. **Целевая IA:** на телефоне — плоский timeline + короткие ярлыки проектов, а не постоянное дерево папок. Одна основная ось — **Projects**, два состояния — **Pinned** и **Archived**, модель — метаданные, а не папка.
3. **В чате главный объект — сам чат, а не модель.** Сейчас в шапке `ChatPane` показывается имя модели; заголовок чата не виден вообще. Меняем: title 17/24, модель и контекст — в subtitle.
4. **Reasoning (Qwen/Bonsai `<think>`) должен быть свернут по умолчанию:** «Reasoning · 12 s», раскрытие по тапу, копирование ответа без reasoning. Сырые теги в тексте — недопустимы.
5. **Локальный контекст — first-class.** Meter после 60%, действия «Compact / Increase / New chat», блокировка на 100%; финальная строка статистики, live-статистика — по желанию.
6. **Настройки:** 8 разделов, 5–7 контролов на экран, progressive disclosure, у каждого поля — «Default / Custom» и сброс. Иерархия: chat > project > model profile > global.
7. **Быстрые победы:** 15 улучшений, из них 8–9 дают максимум пользы при малом объёме кода (шапка, long-press действия, группы по времени, черновики, reasoning, stop/continue, copy/export, empty states).
8. **Не копировать:** вложенные папки на телефоне, «зоопарк понятий» Msty (workspaces + projects + personas + crews + forge), feature-tiles AI Edge Gallery, плоский список Ollama без гигиены, 5-режимный model picker ChatGPT.

**Вердикт в одну таблицу:**

| Вопрос | Ответ |
|---|---|
| Сколько осей организации? | Одна основная — Projects. Tags — вторичны и выключены по умолчанию. Model — фильтр, не папка. |
| Что на телефоне? | Плоский timeline + секция Projects-ярлыков. Без постоянного дерева и без drawer-only истории. |
| Что в чате? | Заголовок чата, модель вторично; reasoning collapsed; stop/continue; context meter; per-chat overrides. |
| Настройки? | 8 разделов, advanced disclosure, «Default/Custom», поиск по настройкам — позже. |
| Что не делать? | Папки по моделям, 3+ уровня вложенности, цветные ряды, unread-бейджи везде, фейковая статистика. |

### 2.2. LM Studio

- Папки чатов, вложенность, drag-and-drop чатов и папок, duplicate, split view двух чатов.[^lm-chat]
- Поиск по всем чатам и «Find in Chat»; поиск по всем чатам индексирует только сообщения, без reasoning/tool-блоков.[^lm-search]
- «Regenerate» сохраняет предыдущие генерации и переключает стрелками; есть branch, conversation notes, token count/context, per-model defaults, presets из system prompt + параметров.[^lm-030]
- Presets — это переносимые JSON-файлы; можно собрать библиотеку промптов.[^lm-presets]
- **Берём:** варианты ответа стрелками, presets, split view на планшете, token count.
- **Не берём:** вложенные папки и desktop-плотность на телефоне; документация LM Studio делает ставку на папки, а не на pin/archive/tags, поэтому как эталон архива его не берём.

### 2.3. Ollama (app)

- Новое приложение с июля 2025: скачивание моделей, чат, drag-and-drop файлов/PDF, изображения для мультимодальных моделей, настройка context length.[^ollama-app]
- Список чатов — плоский; нет папок, pin, tags, массовых действий. В 2026 всё ещё открыт запрос на «Select All / Clear History».[^ollama-issue]
- **Берём:** простоту первого запуска, понятную настройку контекста, capability-gating для изображений.
- **Не берём:** плоский список без гигиены. Ollama хорош как «запустить и поговорить», но не как дом для 100 чатов.

### 2.4. Jan

- Projects группируют чаты, ассистентов и файлы в одну рабочую область; есть custom assistants с системными промптами, локальный OpenAI-совместимый API, MCP, web search, per-model settings (v0.8.4+).[^jan-docs][^jan-review]
- **Берём:** проект как контейнер контекста + ассистент как переиспользуемый пресет; идею «project + assistant», но не два параллельных механизма на телефоне.
- **Не берём:** пересечение понятий assistant/project/model; на телефоне это быстро превращается в три разных способа начать чат.

### 2.5. Msty

- Иерархия Workspaces → Projects/child projects → conversations; Recents включает pinned; Archive — отдельная папка; сортировка и display-настройки: скрыть Recents/Archive/пустые папки/количество чатов; bulk move/delete через Shift/Ctrl; auto-archive по возрасту.[^msty-organize]

- **Берём:** visibility-тумблеры (Recents/Archive/empty/counts), bulk-действия, auto-archive, branch compare, «thinking effort» как понятный уровень.
- **Не берём:** «зоопарк» Personas/Crews/Forge/Shadow Persona. Для нашего приложения это лишние сущности; пользователь должен видеть «проект, чат, сообщение», а не пять типов контейнеров.

### 2.6. Open WebUI

## 3. Информационная архитектура Chats для SnapdragonLLM

### 3.1. Принципы

1. **Chats — дом.** Список чатов — главный экран; чат — push. Никакого hamburger-only.
2. **Одна ось — Projects.** Папки, теги и модели не конкурируют за место в основном списке.
3. **Телефон — timeline, планшет — tree.** На телефоне projects — короткие ярлыки; на планшете их можно раскрывать в list-pane.
4. **Состояния, а не папки.** Pinned и Archived — состояния чата, а не отдельные сущности.
5. **В чате — чат, а не модель.** Заголовок чата первичен; модель — метаданные и элемент управления в композере.
6. **Локальный контекст виден.** Пользователь должен понимать, сколько токенов осталось и что будет при переполнении.
7. **Ничего не теряется.** Черновики, partial-ответы, ветки и архивы сохраняются; удаление — с подтверждением и undo, где возможно.

Внедрение поэтапное: P0 — гигиена списка и чата; Projects — P1, но поля `projectId` и `updatedAt` закладываем сразу, чтобы не мигрировать дважды.

```
│ Older                                        │
│ [Q] Rust FFI notes                 Nov 5     │
```

**Правила:**

- **Pinned** — максимум 5 строк, затем «All pinned». Pinned-чаты не дублируются в Recents.
- **Projects** — секция появляется только если есть хотя бы один проект; 3 строки + «All projects». Строка проекта — навигация, не раскрывающийся список на телефоне.
- **Recents** — все остальные чаты, включая проектные; проектный чат несёт маленькую точку/метку проекта. Это лучше, чем прятать проектные чаты: пользователь не задаёт вопрос «куда пропал чат». В фильтре есть «Unfiled only», если нужно.
- **Группы:** Today, Yesterday, Previous 7 days, Older. Заголовки sticky, 12/16 uppercase, ink-3.
- **Поиск** — раскрывается inline под заголовком; на телефоне может быть full-screen overlay с клавиатурой. Плейсхолдер «Search chats», не «Search».
- **Filter & sort** — одна иконка в правой части строки поиска/заголовка; открывает sheet:
  - Show: Active / Archived
  - Sort: Last activity / Created / Title
  - Model: Any / Clover / Bonsai / Qwen
  - Project: Any / Unfiled / <projects>
  - Attachments: Any / With
  - Date: Any / Today / 7 days / 30 days
  - Reset; на иконке badge с числом активных фильтров.
- **Overflow** (не на первом плане): Select chats, Archived chats, Manage projects. Не дублировать Settings.
- **Bulk select:** long-press строки → selection mode; top bar «3 selected» + close; bottom action bar: Move, Pin/Unpin, Archive, Delete, Export. Delete — последним, danger, с подтверждением. На планшете — Shift-click и drag-to-project.
- **Unread/activity:** точка 6 px для «ответ пришёл, пока вас не было» и spinner для генерации; без красных counts на каждом чате. Счётчик — только у проекта, если он есть.
- **Sort по модели** — только фильтр, не группа. Чат может сменить модель; модель не является стабильной идентичностью.

| Title | 15/20, 500, одна строка, ellipsis |

Не показывать одновременно 4 цвета и 3 бейджа. Одна строка — один акцент.

```
│ 38% · 1,560 / 4,096                         │

```

**Top bar (56 dp):** back 48, title 17/24 (tap → rename), subtitle 12/16 «Model · context · backend · %». Overflow 48: Chat settings, Search in chat, Export, Branch, Clear, Delete. Никакого model name в `<h2>`.

**Messages:** user — bubble surface-2, max 82%, radius 16; assistant — full width, max 72 ch, avatar 24 + model name + time on long-press. Группировка 8 dp внутри группы, 20 dp между. Дата-разделители тонкие, не карточки.

**Reasoning block:** строка над ответом: chevron + «Reasoning · 12 s» (или «Thinking… 00:12» во время стрима), 12/16, ink-3. Раскрытие — surface-2, 1 px border, 13/20, max-height 320 dp, scroll. Автосворачивание после завершения, если пользователь сам не раскрыл. Настройка: On tap (default) / Expanded / Hidden. Копирование ответа — без reasoning; «Copy with reasoning» — в overflow.

**Message actions:**

| Роль | Действия |
|---|---|
| User | Copy, Select text, Edit, Branch from here, Delete |
| Assistant | Copy, Copy with reasoning, Select text, Regenerate, Branch from here, Read aloud (P2), Delete |

На телефоне — long-press → sheet; на планшете — hover icon row. Кнопки 48 dp, destructive — danger text, не красная заливка.

**Regenerate / ветки:**

- Regenerate на последнем ответе создаёт вариант, не затирая старый; в шапке сообщения «2 / 3 ‹ ›».
- Regenerate на старом ответе / Edit user message создаёт ветку: последующие сообщения остаются в исходной ветке; показываем предупреждение и undo snackbar.
- «Branch from here» дублирует чат до сообщения в новый чат с title «(branch)»; это дешевле полноценного дерева.
- Полное дерево веток — P2, sheet со списком ветвей и временем.

**Stop / Continue:**

- Send превращается в Stop; остановка ≤200 ms; partial сохраняется и помечается «Stopped after 312 tokens».
- Действия: Continue (продолжить с места остановки; если движок не умеет — честно отправить «Continue exactly where you left off» как user-сообщение), Regenerate, Copy.
- Черновик не теряется; повторный send во время генерации — диалог «Stop and send?», без скрытой очереди.

**Статистика:**

- После ответа — одна строка 12 mono: `24.1 tok/s · 312 tok · TTFT 4.2 s · ctx 38%`.
- Tap → sheet: prompt tokens, generated, prefill, decode, KV MB, RSS, backend, thermal. Это не загромождает чат.
- Для локального приложения «стоимость» — это не деньги, а **время, RAM, нагрев и батарея**. Поэтому в detail sheet показываем tok/s, TTFT, KV/RSS, thermal и оценку времени до конца, а не `$`. Если появится энергопрофиль — можно добавить mAh/°C, но не в основной строке.
- Live-статистика — тумблер в Chat behavior, по умолчанию off. Для Clover 0.6 tok/s полезно видеть прогресс, но не на каждом чате.

**Context meter:**

- 2 px над композером; появляется после 60%; 60–84% neutral, 85–99% warning, 100% — композер блокируется.
- Tap → sheet: breakdown (system/history/attachments), «Compact history», «Increase context», «New chat with summary», «Trim oldest» (advanced).
- Никогда не обрезать историю молча. При 100% — объяснить и дать действия.

**Ошибки:** inline-card над композером, title человеческим языком, details раскрываются, run_id копируется.

| Ситуация | Title | Действия |
|---|---|---|
| OOM | «Not enough memory for Clover at 4K» | Use 2K, Switch to Qwen, Close other apps |
| Context full | «Context is full (4,096 tokens)» | Compact, Increase, New chat |
| Bad GGUF | «Model file is incomplete» | Re-import, Check SHA, Choose another |
| Thermal | «Phone is hot; speed is limited» | Pause 2 min, Lower threads |
| Vision missing | «This model can't see images» | Add mmproj, Switch model |
| Disk full | «Not enough storage» | Manage models, Free space |
| Engine crash | «The engine stopped» | Restart, Copy diagnostics, Switch model |

Никаких `llama_load_model_from_file failed` в заголовке. Raw-код — в details.

### 3.6. Композер

- Multiline 1–8 строк, max 160 dp; attach `+` слева, model pill, send/stop справа.
- Model pill: визуально 28 dp, tap target 48 dp; короткое имя, status dot, chevron; tap → model sheet; long-press → chat settings.
- `+` sheet: Photo, Camera, File, Audio, Video. Каждый пункт disabled с причиной, если capability нет: «Requires vision model (mmproj)», «Audio is not available in this build». Не скрывать — иначе пользователь не понимает, почему нельзя.
- Превью вложения 64 dp, размер, remove; оценка RAM/токенов до отправки.
- На телефоне Enter — новая строка, отправка кнопкой. На планшете Enter — send, Shift+Enter — newline; тумблер «Enter sends» только на планшете.
- Клавиатура: `WindowInsets.ime` / `adjustResize`; композер над IME; bottom nav скрывается; back сначала закрывает клавиатуру.
- Draft сохраняется per chat; при уходе из пустого нового чата — «Discard draft?» или автоудаление пустого draft.

### 3.7. Вложения и vision

- **Photo/Camera** — только если у модели есть mmproj и vision включён; иначе disabled с причиной.
- **File** — текст/markdown/PDF (извлечение текста); показывать оценку токенов; «Attach as text»; RAG — позже.
- **Audio** — disabled до появления Whisper; **Video** — disabled/P2 с оценкой «8 frames at 384 px».
- Vision per chat: on/off; выключение экономит память/время. Глобально: image max edge 768 px (512/768/1024), max images per message 1, downscale on.
- Path ошибки: если пользователь прикрепил изображение к text-only модели — ошибка **до** отправки, а не после.

### 3.8. Пустые состояния и onboarding

- **Нет чатов:** «No chats yet», primary «Start a chat», secondary «Import a model». Без hero-логотипа.
- **Нет модели:** карточка «Set up a model»: Qwen 0.5B — recommended, Bonsai — balanced, Clover — «Large models». Composer виден, но send открывает model sheet.
- **Пустой чат с моделью:** «Ask anything» + 3 chips под модель (Summarize, Explain, Write) + capability hint «Text only · 4K context».
- **Нет результатов поиска:** показать запрос, «Include archived» toggle, «Clear search».
- **Пустой проект:** «No chats in this project» + New chat.
- **Загрузка модели:** status card с фазами Open → Map → Context → Warm и Cancel; композер не блокируется, первый send ставится в очередь.
- **Onboarding:** 1) privacy/offline, без аккаунта; 2) карточка устройства + рекомендованная модель; 3) optional calibration (Skip); 4) первый чат с 3 chips. Notification permission — при первой генерации, не на старте.

| Шаг | Время | Содержание |
|---|---|---|
| 1 | 0–5 s | «Private AI on this device»: офлайн, чаты здесь, аккаунт не нужен; Continue + Restore chats |
| 2 | 5–15 s | Устройство и модель: Qwen 0.5B — recommended; Bonsai — balanced; Clover — «Large models», без автозагрузки |
| 3 | 15–25 s | «Measure this device (20–30 s)» + Skip; без театра бенчмарков |
| 4 | 25–30 s | Первый чат: 3 prompt chips; модель грузится при первом send, с фазами и Cancel |

### 3.9. Планшет

- Rail 80 + list 340 + chat; list: Pinned, Projects (expandable), Recents; selected chat сохраняется.
- Chat header 64; back не сбрасывает selection; right details sheet 360 вместо постоянной третьей панели.
- Drag-and-drop чата в проект; Shift-click selection; hover actions.
- Ширина текста 720; composer 760; формы 640.
- Поворот сохраняет selected chat, scroll, draft и открытый sheet. При 600–839 dp — bottom bar + одна панель; при <600 — телефонный каркас.

Открывается long-press на model pill или из overflow. Секции:

1. **Model** — select, status, RAM estimate; «Switch reloads model if needed».
2. **Behavior** — system prompt (textarea), preset, temperature, top-p, max tokens, context limit.
3. **Capabilities** — LoRA (select + scale), Vision (switch, if mmproj), reasoning effort.
4. **Advanced** — seed, stop sequences, prompt template (только если включено).

У каждого поля: `Default (0.7)` / `Custom`, reset-иконка, «Reset all to defaults». Внизу — «Save» (или автосейв с undo). Не показывать backend/storage здесь. Если меняется context limit или модель, показываем предупреждение «Reloads the engine; chat history is preserved» — как в Tuning.

**Precedence:**

```
Chat custom
  ↓
Project default
  ↓
Model profile (model + device)
  ↓
Global default
  ↓
Built-in
```

Проект задаёт default model для новых чатов, но **не** меняет модель существующих. Это правило LibreChat стоит сохранить.

## 6. 5 долгосрочных идей

1. **Память и поиск по истории на устройстве.** Гибрид FTS + embeddings (EmbeddingGemma-подобная модель), ответы на вопросы «что мы решали про Clover?» с цитатами и переходом к сообщению. Приватно, без облака. Это превращает архив чатов в базу знаний.
2. **Дерево веток + split view / compare.** Полноценное дерево regenerate/edit и две панели на планшете: два чата или две модели рядом, синхронный скролл, «выбрать лучший». LM Studio/Claude уже показывают ценность; на телефоне — позже, на планшете — раньше.
3. **Projects как knowledge workspace + side chats.** Файлы, RAG, project instructions, default preset, «side chat» для вопроса мимо основного треда (Claude 2026). Не смешивать с основной историей; side chat читает контекст, но не засоряет его.
4. **Context compaction и KV reuse.** Rolling summary, авто-компакция при 85%, быстрый resume за счёт KV-кэша; маленькая локальная модель для суммаризации. Это прямой ответ на «chat infinitely» AI Edge и context card Claude.
5. **Зашифрованный backup и перенос между устройствами.** Экспорт всей библиотеки, импорт с merge, Wi-Fi/WebDAV-бэкап без облака, шифрование паролем. Локальные чаты — ценность; их потеря — худший UX.

MCP/tools и agentic-сценарии — отдельный трек, не в IA чата v1. Если делать, то как «Skills» внутри проекта, а не как ещё одну вкладку.

## 7. Как красиво разделять чаты: папки, проекты, теги, модели

### 7.1. Формула

**Одна ось, два состояния, три уровня.**

- **Одна ось:** Projects. Только они создают иерархию.
- **Два состояния:** Pinned и Archived. Это флаги, не папки.
- **Три уровня:** Root → Project → Chat. Tags — метки, не уровень.
- **Model** — метаданные и фильтр. Никогда не папка.

### 7.2. Projects

| Свойство | Решение |
|---|---|
| Назначение | Группа чатов с общим контекстом: default model, instructions, preset, LoRA/vision |
| Вложенность | 1 уровень на телефоне; 2 — максимум на планшете; данные поддерживают `parentId`, но UI не поощряет вложенность |
| Визуал | 2-буквенная монограмма или 6 px цветная точка; 1 px border; без emoji и фоновых картинок |
| Строка | 64 dp: имя 15/20, meta «12 chats · 2h», chevron; выбранный — surface-2 |
| Создание | Из «Move to project» → «New project…»; только имя, остальное — в настройках |
| Пустой проект | «No chats in this project» + New chat; не показывать пустые папки в корне |
| Удаление | Удаляет папку, чаты возвращаются в Recents; confirm |
| Цвета | 6 приглушённых из темы; только точка/полоска, не заливка ряда |

### 7.3. Tags

- Включаются в Settings → Chat behavior → «Tags» (off by default).
- Максимум 5–6 тегов, нейтральные chips `#topic`, без радуги.
- Показываются в деталях чата и в поиске; на строке — максимум один тег, и только если включено.
- Поиск: `tag:work`, `tag:none`.
- Не делать «папки тегов», не дублировать проект тегом. Если чат уже в проекте, тег нужен только для сквозной темы (например, `#research`).

### 7.4. Model

- Показывать 6 px точкой + коротким именем в meta строки.
- Фильтр в Filter & sort: «Model: Clover / Bonsai / Qwen».
- Project может иметь default model; чат может переопределить.
- Не группировать Recents по модели: чат, сменивший модель, «переедет» и сломает мышечную память.

### 7.5. Pinned и Archived

- Pinned — секция сверху, max 5 видимых, «All pinned»; pin не меняет `updatedAt`.
- Archived — состояние; доступ через Filter & sort → Show: Archived; поиск по архиву — с `Include archived`. Не держать Archive отдельной папкой в корне.
- Auto-archive — опция (Never по умолчанию); если включена, показывать «Archived 30+ days ago» и не удалять.

### 7.6. Сценарии

| Масштаб | Что показывать |
|---|---|
| < 10 чатов | Только Pinned + Recents. Projects не создавать, пока пользователь сам не захочет |
| 10–50 | 2–4 проекта; проектные чаты остаются в Recents с точкой; tags — по желанию |
| 50+ | Projects + Filter & sort + Archive + поиск; tags для сквозных тем; bulk select |
| 200+ | FTS, фильтры, «Unfiled only», auto-archive; виртуализация списка |

### 7.7. Чек-лист «не колхоз»

- [ ] Одна ось иерархии — Projects.
- [ ] Не больше 2 уровней на планшете, 1 — на телефоне.
- [ ] Один акцент + 6 приглушённых project-цветов; без цветных рядов.
- [ ] Без emoji-папок и фоновых картинок.
- [ ] Без папок по моделям.
- [ ] Без дублирования «All chats» и «Recents».
- [ ] Без unread-бейджей на каждом чате.
- [ ] Без тегов на каждой строке.
- [ ] Archive — состояние, не папка.
- [ ] Pinned — секция, не pinboard.
- [ ] Поиск и фильтр всегда доступны, но не занимают пол-экрана.

| Тумблер | Дефолт | Что скрывает/меняет |
|---|---|---|
| Projects & folders | Auto (появляется после первого проекта) | Секцию Projects; можно скрыть, проекты останутся в данных |
| Tags | Off | Chips тегов, `tag:` в поиске |

| Archived | On (скрыт, пока не используется) | Пункт Show: Archived |
| Activity dots | On | Точки/спиннеры в списке |
| Live stats | Off | Строку во время генерации |
| Final stats | On | Строку после ответа |
| Context meter | After 60% | Meter и предупреждения |
| Reasoning | On tap | Блок reasoning; Hidden — не показывать |
| Timestamps | On long-press | Время в сообщениях |
| Model marks | On | Монограммы в списке и у ответов |
| Prompt chips | On | 3 chips в пустом чате |
| Haptics | On | Тактильный отклик |
| Advanced generation params | Off | Seed, stop sequences, top-k и пр. |
| Developer mode | Off | Logs, raw config, benchmark |
| Incognito chats | On | Пункт в меню нового чата |
| Screen capture protection | Off | FLAG_SECURE |
| Auto-archive | Off | Автоархив по возрасту |

**«Clean chat»** — один переключатель для не-технических пользователей: live stats off, final stats on, timestamps on long-press, reasoning on tap, model marks off, tags off, activity dots on, prompt chips on. Это не отдельный режим интерфейса, а пресет, который можно переопределить.

**Правило:** никогда не скрывать Stop, контекстное предупреждение, подтверждение удаления, undo и кнопку поиска.

## 9. Мобильный UX, доступность, тема, motion

### 9.1. Одна рука и жесты

- Основные действия — в нижней трети: send/stop, attach, model pill, context actions.
- В top bar — только back, title, overflow. Никаких destructive-кнопок в правом верхнем углу.
- Long-press — основной жест для действий над чатом/сообщением; не прятать критичное только в swipe. В WebView: pointerdown 450 ms + `contextmenu.preventDefault()`; на сообщении long-press открывает sheet, а «Select text» уже включает нативное выделение. Не вешать long-press на code blocks и внешние ссылки.
- Не делать swipe-to-archive на строках: конфликт с системным back и случайные архивы. Если очень нужно — только на планшете.
- Predictive back (Android 14+ `OnBackInvokedCallback`): из чата → список с сохранённой позицией; из sheet → закрыть sheet; back во время генерации не отменяет её.
- Bottom nav скрывается в чате и при IME; на планшете rail остаётся.

### 9.2. Клавиатура, safe area, IME

- `100dvh`, `env(safe-area-inset-*)`, `WindowInsets.ime` / `adjustResize`; composer над клавиатурой.
- На телефоне Enter = newline, отправка кнопкой. На планшете Enter = send, Shift+Enter = newline. Текущий код отправляет по Enter на всех платформах — исправить.
- При фокусе композера не должно быть прыжка layout: сначала IME, потом скрытие bottom nav (в коде уже есть задержка 200 ms — сохранить).
- Проверить 3-button navigation и gesture navigation, landscape, split-screen 600–839 dp.

### 9.3. Длинные ответы, markdown, code

- Коалесить токены раз в 80–120 ms, не ререндерить всё на каждый токен.
- `content-visibility: auto` / виртуализация для длинных списков; `contain` на сообщениях.
- Автоскролл только если пользователь внизу; иначе — pill «Jump to latest» и divider «New messages».
- Markdown: заголовки, списки, таблицы (горизонтальный скролл), ссылки с подтверждением, без remote images по умолчанию.
- Code block: language label, copy всегда видим, collapse после 20 строк, wrap toggle, горизонтальный скролл. Для блоков >200 строк — без тяжёлой подсветки, чтобы не ронять WebView на SD845.
- Таблицы и код не должны ломать ширину 720; `overflow-x: auto` внутри блока, не на всей странице.

### 9.4. Reasoning

- Парсер: `<think>`, `</think>`, `<thinking>`, `<reason>`, `<reasoning>`, `<thought>`, а также отдельные поля `reasoning_content` / `reasoning` / `thinking` (как в Open WebUI).[^owui-reasoning]
- Состояние парсера должно переживать разрыв тега между чанками; не показывать сырые теги даже на один кадр.
- Во время стрима: «Thinking… 00:12» + Stop доступен; после — «Reasoning · 12 s» свернуто.
- Не отправлять reasoning обратно в модель по умолчанию (для local llama.cpp это может ухудшить шаблон); хранить для отображения.
- Копирование ответа — без reasoning; «Copy with reasoning» — отдельным пунктом.
- Screen reader: «Reasoning, 12 seconds, collapsed, button»; live region — не чаще 1 раза в 2 s.

### 9.5. Доступность

- Все tap targets ≥48 dp, между ними ≥8 dp; icon 24 внутри 48.
- Контраст body ≥4.5:1, large ≥3:1; accent не единственный носитель смысла.
- Font scale 1.3× и 2.0×: bubbles wrap, stat line переносится, кнопки растут, ничего не обрезается.
- Semantics: список сообщений — list; «You said» / «Clover said»; model pill — «Model Clover 35B, 4K context, loaded»; context meter — `aria-valuenow`.
- Focus ring 2 px accent + 2 px offset; sheet focus trap; Esc закрывает sheet; Ctrl+K — поиск, Ctrl+N — новый чат, Ctrl+Enter — send (планшет).
- Ошибки — inline, не snackbar; snackbar только для undo/подтверждений.

### 9.6. Тёмная тема и reduced motion

- 5 тем уже есть; сохранить System/Light/Dark/Night/AMOLED.
- AMOLED: true black canvas, но текст не чистый белый (`#E8E4DA`), границы `#2C3036`; code bg `#16181B`.
- Reduced motion: `prefers-reduced-motion` + `data-motion="off"`; 80 ms crossfade вместо transform; без bounce, pulse, shimmer, glow.
- Streaming caret — step 1 s, не бесконечная пульсация; при reduced motion — статичный.
- Haptics — только на send/stop/selection, не на каждый токен.

## 12. Краткое резюме и приоритеты

### Резюме

SnapdragonLLM уже имеет правильный каркас: Chats как главный экран, tablet split, честные метрики, хорошую тему и motion. Но раздел Chats пока — «список + поиск», а не рабочее пространство. Конкуренты 2025–2026 сходятся в трёх вещах:

1. **Список чатов должен уметь больше, чем показывать.** Pin, archive, поиск, проекты, действия и группы по времени — это не «фичи для власти», а базовая гигиена.
2. **В чате важнее контекст и управление генерацией, чем украшения.** Заголовок чата, reasoning, stop/continue, ветки, context meter, понятные ошибки.
3. **Организация должна быть одной осью.** Projects + поиск + pin/archive. Tags — опция; model — фильтр; вложенные папки — только на планшете.

Мы не должны копировать desktop-плотность LM Studio, «зоопарк» Msty, feature-tiles AI Edge или плоский список Ollama. Наш путь: **простой timeline на телефоне, проекты как контекст, честный локальный контекст, аккуратные настройки.**

### P0 — сделать сейчас (гигиена и доверие)

1. Заголовок чата в шапке, модель — в subtitle.
2. Long-press действия: Pin, Rename, Archive, Delete, Export (Move to project — вместе с P1).
3. Группы Today/Yesterday/7 days/Older; Pinned max 5.
4. Rename + auto-title из первого сообщения (без вызова модели).
5. Черновики и новый чат как draft.
6. Smart autoscroll + «Jump to latest» + unread divider.
7. Collapsible reasoning для `<think>`/reasoning-полей.
8. Stop → partial → Continue; финальная статистика; context meter 60% + действия.
9. Copy/export sheet (Markdown, plain, .md/.json, share file).
10. Empty/no-model state + onboarding без 12 GB-модели.

### P1 — следующий шаг (мощность без перегрузки)

1. Вложения с capability-gating (vision/mmproj).
2. In-chat search.
3. Regenerate variants + edit → branch.
4. Per-chat settings sheet + 3 presets + Default/Custom.
5. Projects (один уровень) + project screen + default model/instructions.
6. Полнотекстовый поиск по сообщениям + Filter & sort sheet.
7. Bulk select (long-press → selection mode).
8. Settings restructure: 8 разделов, advanced disclosure.

### P2 — после подтверждения сценариев

1. Tags UI + `tag:` search.
2. Split view / compare на планшете.
3. Branch tree sheet.
4. Semantic memory / «ask your history» с цитатами.
5. Encrypted backup / Wi-Fi sync.
6. Side chats.
7. Project knowledge/RAG.
8. MCP/tools как отдельный трек.

### Критерий успеха

Пользователь на MI 8 должен за **два действия** найти или начать чат, за **один long-press** — переименовать/закрепить/убрать, и ни разу не потерять ответ из-за остановки, переполнения контекста или поворота экрана. Если это работает, сложные фичи можно добавлять без страха.
