# 07 — Протокол измерений

## Принципы

1. **Число без контекста — не число.** Всегда: модель + хеш файла + квант + устройство +
   конфиг + промпт + задача + число прогонов + thermal.
2. **chat ≠ raw, prefill ≠ decode.** Не смешивать в одной цифре.
3. **Один бинарник, одна сессия, чередование A/B.** Иначе разница — это нагрев/фон.
4. **Append-only.** Старые записи не редактируем; невоспроизведённое помечаем.
5. **Сначала прогрев, потом замер.** Первый прогон — warm-up, в статистику не идёт.

## Подготовка устройства

- Авиарежим, Wi-Fi выключен (или стабильная сеть, но без трафика).
- Батарея 50–80%, **не на зарядке** (зарядка греет).
- Экран включён, яркость 50%, авто-яркость off, таймаут длинный.
- Все фоновые приложения закрыты; Recent очищен.
- Устройство остыло: 10 минут покоя, температура батареи записана.
- Термочехол снят; не на солнце; комнатная температура записана.
- Для 845: проверить, что не включён режим энергосбережения.

## Задачи

| Задача | Что меряем | Промпт |
| --- | --- | --- |
| `chat` | TTFT, prefill tok/s, decode tok/s через API приложения | `bench/prompt.txt` (сохранённый, ~1900 токенов) |
| `raw` | скорость продолжения текста движком | тот же файл, без chat-обёртки |
| `prefill-only` | токены/с на длинном промпте | 2K/4K/8K/16K/32K |
| `decode-long` | устойчивая скорость на 256–512 токенах | короткий промпт |
| `sustained` | 10–30 минут, деградация от нагрева | циклический чат |
| `quality` | правильность ответов | 22 промпта + мобильные |

`chat` — это запрос через приложение/сервер; `raw` — продолжение текста. **Никогда не
публиковать `raw` как скорость ответа.**

## Серия замеров

- **8 прогонов** на конфиг (минимум 5).
- Первый — warm-up, отбрасывается.
- Между прогонами 15–30 с паузы; проверять thermal.
- Если thermal status изменился (например, `MODERATE` → `SEVERE`), серия помечается.
- A/B: чередовать A, B, A, B… в одной сессии.
- Результат: медиана + min/max; среднее не прячет выбросы.

## Что записывать (минимум)

## Длинный контекст

Отдельные серии: 2K, 4K, 8K, 16K, 32K. На каждом — TTFT, prefill, decode, peak RAM,
hit rate. Строим кривую; не экстраполируем с 2K на 32K.

## Устойчивость (sustained)

- 10–30 минут непрерывной генерации.
- Каждые 60 с — запись tok/s, температуры, thermal status, частот.
- Считаем: скорость в первые 2 минуты, в конце, процент деградации.
- Это важнее «пиковой» цифры: телефон в руке греется.

## Quality gate

### Базовый (из 4 GB проекта, `bench/quality-prompts.json`)

22 промпта: арифметика, логика, код, который должен запускаться, tool loop из трёх
вызовов, RU/DE/ES, instruction-following, три факта в ~18K токенов.

- 2 повтора на промпт.
- Оценка: прошёл/не прошёл по заранее описанному критерию (не «нравится/не нравится»).
- Для сравнения квантов/бэкендов — одинаковые параметры сэмплинга.

### Мобильные добавления

- tool call в формате приложения;
- JSON по схеме;
- русский и английский;
- длинный контекст (needle);
- отказ от галлюцинации при отсутствии ответа в тексте;
- короткий ответ на короткий вопрос (не льёт 2000 токенов).

### Правило

Скорость без quality gate не считается улучшением. Если quality просел — изменение
отклоняется или помечается как экспериментальное.

## Невоспроизведённый результат

Если число не повторилось:

```
2026-11-07  clover  chat  8.3  (7.9–8.8)  ...  воспроизведено
2026-11-08  clover  chat  11.2 (10.9–11.4) ...  NOT REPRODUCED: 9.1 (8.7–9.4) в той же сессии
```

Старую строку не удаляем; новую пишем рядом с пометкой.

## Инструменты

- Встроенный benchmark runner (см. `05-LOGGING-TUNING.md`).
- `adb shell dumpsys thermalservice`, `dumpsys meminfo`, `dumpsys batterystats`.
- `perfetto` для трейсов (опционально): CPU/GPU/I/O.
- `simpleperf` для профиля CPU (если доступен без root).

## Запреты

- Не мерить во время установки APK, скачивания модели, сборки, зарядки.
- Не мерить на горячем устройстве, если серия заявлена как «холодная».
- Не сравнивать 845 и 8 Elite по одной цифре: разные устройства, разная память.
- Не публиковать число, снятое с другим промптом, как «то же самое».
